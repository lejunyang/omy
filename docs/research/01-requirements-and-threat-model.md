# 01 · 需求与威胁模型

## 1. 产品定位

omy 是一个**开源、跨平台、本地优先**的加密文件管理应用。

与传统加密工具（7-Zip、VeraCrypt、age）的核心差异：**加密后的文件依然可直接浏览和播放**，无需先完整解密到磁盘。

### 1.1 一句话描述

> 把文件加密成 `.omy`，然后像用普通文件管理器一样浏览它们——视频能拖动播放，图片有缩略图，文件名正常显示。

### 1.2 目标用户

- 在共享设备/云盘上存放私密文件的个人用户
- 需要在多设备间安全访问同一批文件的用户
- 对开源、可审计、无云依赖有要求的技术用户

## 2. 威胁模型

> **这是整份设计的地基。** 所有安全取舍都由本节推导而来。

### 2.1 防护目标（In Scope）

| # | 威胁场景 | 具体描述 | 防护手段 |
|---|---|---|---|
| T1 | **设备丢失/被盗** | 笔记本、手机丢失，拾得者尝试读取文件 | 静态数据全量 AEAD 加密 |
| T2 | **云盘运营商 / 同步服务** | 文件同步到 OneDrive / iCloud / NAS，服务方或其员工可访问 | 密文上传，密钥永不出本机 |
| T3 | **共享设备的其他使用者** | 家人、同事使用同一台电脑，随手翻看文件 | 文件名加密 + 密码解锁 |
| T4 | **离线暴力破解** | 攻击者拷走密文文件，在自己机器上无限时间爆破 | Argon2id 内存硬 KDF |
| T5 | **密文篡改** | 攻击者修改密文，试图让用户解密出被污染的内容 | AEAD 认证 + header MAC |
| T6 | **块级攻击** | 重排、截断、跨文件移植密文块 | nonce 绑定块序号 + AAD 绑定文件 UUID + final 标记 |
| T7 | **降级攻击** | 篡改 header 中的 KDF 参数（如 m=64MiB → 8KiB）使爆破变易 | header MAC 覆盖全部参数 |
| T8 | **局域网窃听** | 同一 WiFi 下的其他设备嗅探传输内容 | 端到端加密信道 + 只传密文 |

### 2.2 明确的非目标（Out of Scope）

> ⚠️ **开源项目必须诚实声明能力边界。** 以下场景本设计**不提供防护**，用户不应依赖本工具应对：

| # | 非目标 | 原因 |
|---|---|---|
| N1 | **隐藏"这是加密文件"这一事实** | 设计上就有明显 magic 头。伪装模式仅挡随手点开，`binwalk` 等工具一眼看穿 |
| N2 | **抵抗专业数字取证** | 内存取证、冷启动攻击、SSD 残留数据恢复均不在防护范围 |
| N3 | **抵抗国家级定向攻击（APT）** | 需要的是完全不同的操作安全（OPSEC）体系，软件层面解决不了 |
| N4 | **抵抗设备已被植入恶意软件的场景** | 键盘记录器可直接拿到密码；被 root 的系统上任何本地加密都无意义 |
| N5 | **抵抗胁迫（rubber-hose）** | 可否认性提供**有限**帮助，但不能对抗持续的物理胁迫 |
| N6 | **完全隐藏元数据** | 文件大小、数量、修改时间默认可见（可选功能可部分缓解） |
| N7 | **防止已解锁状态下的截屏/录屏** | 内容一旦在屏幕上显示就无法控制 |
| N8 | **SSD 上的安全擦除** | wear leveling + TRIM 使覆写擦除在物理层面不可靠，本应用**不提供**虚假的"安全删除"功能 |

### 2.3 信任边界

```
┌─────────────────────────────────────────────────────┐
│  受信任                                              │
│  ├── 用户的密码（假定用户自己保管妥当）                │
│  ├── 运行 omy 的操作系统内核                  │
│  ├── OS 密钥库（Keychain / Keystore / TPM）          │
│  └── omy 主进程（持有密钥的唯一进程）          │
├─────────────────────────────────────────────────────┤
│  半受信任（隔离运行）                                 │
│  └── FFmpeg 子进程 —— 降权 + 沙箱 + 不持有任何密钥     │
├─────────────────────────────────────────────────────┤
│  不受信任                                            │
│  ├── 磁盘上的密文文件（假定攻击者可完整获取）           │
│  ├── 云同步服务                                      │
│  ├── 局域网（假定可被嗅探）                           │
│  ├── 待加密的输入文件（可能是恶意构造的）              │
│  └── 局域网对端设备（只给密文，不给密钥）              │
└─────────────────────────────────────────────────────┘
```

### 2.4 由威胁模型推导出的简化

因为 N1~N8 明确排除，以下复杂度**被有意识地砍掉**：

- ❌ 不做隐蔽容器 / 隐藏卷（VeraCrypt 式）
- ❌ 不做 `mlock` 防内存换页（但仍做 `zeroize`，成本极低）
- ❌ 不做流量填充 / 定时抖动等反流量分析
- ❌ 不做防冷启动攻击的密钥分散存储
- ❌ 元数据归一化（时间戳抹平、大小 padding）**默认关闭**，仅作为高级选项

**但以下不能省**（因为 T4 云盘场景下攻击者有无限时间）：
- ✅ Argon2id 参数必须达到 OWASP 推荐基线
- ✅ AEAD 必须是认证加密，不能用裸 CTR/CBC
- ✅ header 必须有 MAC 覆盖

## 3. 功能需求

### 3.1 核心功能（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-01 | 浏览本地文件 | 内置文件管理器，可浏览授权目录，网格/列表双视图 |
| F-02 | 加密文件 | 任意文件 → `.omy`，解密后 bit-for-bit 一致 |
| F-03 | 文件名加密 | 磁盘文件名为密文；可选保留原后缀 |
| F-04 | 可选压缩 | zstd，级别 1–22 可调 |
| F-05 | 强度自定义 | Argon2 档位可选、chunk_size 64KiB–16MiB 可调、AEAD 算法可选 |
| F-06 | 多媒体内嵌预览 | 文本/图片/音频/视频可在应用内直接查看，**无临时明文文件** |
| F-07 | 视频随机 seek | 拖动进度条到任意位置立即播放，P1 路径下延迟 <100ms |
| F-08 | 自定义格式 + 魔数 | 通过文件头识别，可读出加密的原文件名 |
| F-09 | 格式可扩展 | TLV 扩展区，未知字段安全忽略（critical 位除外） |
| F-10 | 分片 | 手动指定分片大小，应用内自动合并预览 |
| F-11 | 多浏览密码 | 最多 8 个凭据 slot，任一命中即可解锁 |
| F-12 | 自动扫描 | 扫描授权目录，自动识别本应用加密文件并匹配密码 |
| F-13 | 局域网共享 | 设备发现、配对、**只传密文**、远程 seek |
| F-14 | 文件夹加密 | 容器模式 + 树形模式，两者都支持 |
| F-15 | CLI | 加解密、header 检视、完整性校验、slot 管理、批量扫描 |

### 3.2 增强功能（P1）

| ID | 需求 | 说明 |
|---|---|---|
| F-16 | 加密缩略图 | 存入 header TLV，列表页秒开；视频可自选封面帧 |
| F-17 | 生物识别解锁 | 通过 OS 密钥库包裹 KEK，**必须保留密码后备** |
| F-18 | 恢复码 | 24 词助记词形式的独立 slot |
| F-19 | 外部应用打开 | Android 走 ContentProvider 不落盘；桌面走受控临时文件 |
| F-20 | 伪装模式 | 宿主格式头（JPEG/PNG/PDF/MP4）+ footer magic 或扩展区两种方式 |
| F-21 | 视频转码 | 加密时可选转为 web 原生格式，**牺牲可还原性换播放性能** |
| F-22 | 外挂字幕加密 | 同名字幕文件一并加密并关联 |
| F-23 | 深色模式 + 多语言 | 简中 / 英文，跟随系统 |

### 3.3 明确不做（首期）

| 项目 | 原因 | 是否留架构 |
|---|---|---|
| ASS/SSA 特效字幕渲染 | 需引入 JASSUB + 字体 fallback，复杂度高 | ✅ 留 TLV 字段与渲染层接口 |
| PGS/VobSub 图形字幕 | 需自行解码位图并贴图 | ✅ 同上 |
| 就地编辑（改后重新加密） | 需引入块版本计数器防 nonce 复用 | ✅ header 预留 `chunk_version` 字段 |
| PDF 内嵌预览 | pdf.js 体积大 | ❌ 走外部应用打开 |
| RAW 图片（CR2/NEF/ARW） | 用户明确不需要 | ❌ |
| 虚拟盘挂载（FUSE/WinFsp/FSKit） | 工程量大，可后置 | ✅ 抽象层预留 |
| 硬件解码 | 各平台原生代码不同 | ✅ 播放路径抽象已预留 |
| 云盘直连 | 非本期范围 | ❌ |

## 4. 非功能需求

### 4.1 性能指标

| 场景 | 目标 | 依据 |
|---|---|---|
| 密码解锁（单个 vault） | < 300 ms（interactive 档） | 实测 Argon2id m=64MiB 约 180 ms |
| 扫描 10000 个文件 × 5 密码 | < 5 s | 实测推算 3.4 s |
| 视频 seek（P1 路径） | < 100 ms | 只需解密 1–2 个块 |
| 列表页缩略图加载 | < 50 ms/项 | 只读 header，不碰载荷 |
| 加密吞吐（无压缩） | ≥ 200 MB/s（现代桌面 CPU） | AEAD 硬件加速 |
| 内存占用（播放 4K 视频） | < 200 MB | 流式处理，不整文件加载 |

### 4.2 兼容性

| 平台 | 最低版本 | 支持程度 |
|---|---|---|
| Windows | 10 (1809+) | 完整 |
| macOS | 11 Big Sur | 完整 |
| Linux | Ubuntu 20.04 / 等价 glibc | 完整 |
| Android | 8.0 (API 26) | 完整（SAF 授权目录） |
| iOS | 14.0 | **降级**：导入式保险箱 + 局域网客户端 |

> API 26 是 `StorageManager.openProxyFileDescriptor` 的最低要求，该 API 是 Android 上"外部应用打开不落盘"的关键。

### 4.3 可靠性

- 加密写入必须原子：临时文件 → fsync → rename
- 断电/崩溃不得产生"看起来正常但实际损坏"的文件
- 解密后自动校验内容哈希（TLV 中的 BLAKE2b-256）
- 移动端后台中断可续传

### 4.4 可审计性（开源要求）

- 格式规范必须完整到第三方可独立实现
- 提供确定性测试向量
- 无任何 security-through-obscurity
- 密码学原语全部使用成熟标准（RFC 9106 / RFC 8439 / RFC 5869）

## 6. 术语表

| 术语 | 全称 / 含义 |
|---|---|
| **FEK** | File Encryption Key，每个文件独立随机生成的 32 字节密钥 |
| **KEK** | Key Encryption Key，由密码经 Argon2id 派生，用于包裹 FEK |
| **slot** | key slot，header 中存放"被某个凭据包裹的 FEK"的固定 48 字节区域 |
| **vault** | 一组共享同一 `vault_salt` 的文件集合，逻辑上的"库" |
| **AEAD** | Authenticated Encryption with Associated Data，认证加密 |
| **TLV** | Type-Length-Value，可扩展的元数据编码方式 |
| **chunk** | 载荷分块的基本单位，默认 256 KiB |
| **shard** | 分片，一个 `.omy` 文件被切分成的多个物理文件 |
| **P1/P2/P3** | 三条播放路径：直通 / 转封装 / 全解码 |
| **SAF** | Storage Access Framework，Android 的用户授权文件访问机制 |
| **security-scoped bookmark** | iOS 上持久化用户授权目录访问权的机制 |
