# 原型 vs 实现 全量对照清单（Telegram 远程位置）

> 对照对象：`docs/research/appendix/telegram-remote-prototype.html`（约 3960 行）
> 与 omy 当前实现。
>
> **核对方式：对着实际运行的 GUI 逐项操作核对，不是读实现代码推断。**
> 这一条不是形式要求——此前踩过：`PlaceBrowser` 里早就有 `@contextmenu`
> 和缩略图渲染代码，却被 `activatable()` 恒返回 false 整个废掉。
> **代码存在 ≠ 功能可用**，基于读代码产出的清单会系统性地偏乐观。
>
> **口径**：原型全绿不能替实现背书，实现跑通也不代表原型描述的交互都做了。
> 这份清单的价值正在于把这两件事分开。

## 八、错误态

| 原型项 | 状态 | 说明 |
|---|---|---|
| `FLOOD_WAIT` 限流等待条 | ⚪ 有意不测 | **不是没验，是决定不验**：要真的触发就得把账号打进限流，而这是用户**唯一**的测试账号，且他此前已被限流堵过一次（那次收不到验证码就是它）。为验一个错误态再把他堵住不值得。后端能识别并带出秒数，有单测覆盖 |
| session 失效 / 损坏 | ✅ 已验证（真机） | 改坏 session 密文后报 `tg_session_unreadable`「读取登录态失败：登录态解不开，需要重新登录」，与「网络连不上」是不同错误码；位置仍留在侧栏而不是消失。**验前备份、验后还原并复查账号可用** |
| `API_ID_PUBLISHED_FLOOD` → 引导填自己 api_id | ❌ 未实现 | 依赖 api_id 界面。**且无法人为构造**：这个错误只有在内置 api_id 被大量第三方客户端共用、触发 Telegram 侧阈值时才出现，不受本地控制 |
| 代理 scheme 不支持 | ✅ 已验证（真机） | `ftp://` 报 `tg_bad_proxy`「不支持的代理类型 ftp，请使用 socks5（或能同时提供 socks5 的混合端口）」。`http://` **不报错**——按设计自动改用同端口 SOCKS5（§7 的归一化）。原型那个「一键改为 socks5://」按钮仍未实现，当前是静默自动转换 |
| 网络不可达 | ✅ 已验证（真机） | 代理指向 `socks5://127.0.0.1:1`，5.1 秒后报 `tg_connect_failed`「连接失败：request error: Proxy server unreachable」，不是静默卡住 |
| 上述错误码在界面上是可读文案而非原始码 | ✅ 已验证（源码核对） | `tg_bad_proxy` / `tg_no_session` / `tg_session_unreadable` / `tg_connect_failed` 在中英两份 `*.errors.json` 里都有对应文案 |
| `file_reference` 过期刷新 | ❌ 未实测 | 仍在未实测清单里（见 §11） |
| CDN 重定向不支持 | ✅ 已验证（单测） | 明确报错而非静默失败；界面有可读文案 |
| 权限受限对话（跨对话搜索时跳过） | ✅ 已验证（真机） | 与限流、网络错误分开处理 |

### 关于「未验证」与「不测」的区别

清单里刻意把三种情况分开写，它们对后来者的意义不同：

- **🟡 未验证**：能验，只是这一轮没排上。后来者可以直接去验。
- **⚪ 有意不测**：能验，但代价不值得（如 `FLOOD_WAIT` 会堵住用户唯一的
  账号）。理由写在条目里，后来者可以重新权衡，而不必重新发现这个代价。
- **无法构造**：不在本地控制范围内（如 `API_ID_PUBLISHED_FLOOD` 取决于
  Telegram 侧阈值）。写清这一点，免得有人反复尝试。

### 未实现里最值得优先的几项

1. **受保护内容那一行告知**（§12.5）——omytest 群就是 `noforwards=true`，
   用户看不到任何说明。实现成本低，且是已写进设计的产品承诺。
2. **统一传输管理页**（§12.5a）——上传已经可用，但没有任何地方能看到
   进度、暂停或重试。
3. **消息视图的加载更早与缩略图**（§12.12.5 #8 #9 #10）——需要后端
   给 `remote_messages` 加分页参数、给 `MessageRow` 加缩略图字段。
4. **api_id 自定义与风险告知**——`API_ID_PUBLISHED_FLOOD` 真的发生时，
   用户当前没有任何自救入口。
5. **tdata 前提检查清单与本地密码**——前者影响可用性，后者是一条
   完全缺失的分支（当前样本没有本地密码，所以一直没暴露）。
