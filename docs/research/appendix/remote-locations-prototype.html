为什么「识别中」要单独成一态：扫 100 个文件要几秒，但第一个 200 ms 就出来了。 整页转圈会让用户盯着空列表白等。

「消失」与「置灰」的分界（沿用 RemoteScreen.vue 已定的规矩）：
· 整个位置永远做不到 → 整项不出现。放个灰按钮反而让人反复去点。
· 当前状态做不到、换个状态就行 → 置灰 + hint 告诉用户下一步。
上面最后一项是可写云盘上的「密码管理」：位置能写，但random_write=false， 所以置灰并说明原因，而不是消失。

4 · 设置（PC：弹窗，左侧分类）
语言与主题从顶栏图标收进来；缓存是其中一项，点进去是二级页
为什么要有这个页面：现在语言（🌐）和主题（◐）是顶栏的两个图标， 移动端底栏也各占一格。底栏换成「文件 / 远程 / 设备 / 设置」后这两格没了， 必须有地方安置；而远程位置又带来缓存、连接、传输等一批新配置—— 散在各处迟早找不到，收进一个设置入口是必然的。
标记说明：带 待实现 的项目前在代码里还不存在， 是这份设计新提出的能力；未标记的已有实现，只需迁到设置页。 逐项核查结果与依赖顺序见文档 §9.2 / §9.7。
其中配置持久化是唯一的硬前置：GUI 目前只有 localStorage 存了语言和主题， 后端完全没有配置模块——而缓存上限、自动锁定这些要由 Rust 侧执行， 前端存了后端也读不到。

移动端三条硬性要求（来自 AGENTS.md 的既有教训）：
· 打开条目必须读 isMobile 走单击分支——触屏没有 dblclick， 只改 CSS 会得到「界面正常但点什么都打不开」，截图和 CSS 审查都发现不了。
· 底栏加 env(safe-area-inset-bottom)，否则手势导航条盖住按钮。
· 长按要 user-select:none 抑制系统文字选择与放大镜。
多一个移动端专属开关：「仅在 Wi-Fi 下缓存」——蜂窝网络下悄悄缓存几 GB 是真实的钱。
