# 远程位置（云盘 / WebDAV / Telegram）

把 NAS、网盘或任何支持 WebDAV 的服务挂成一个「远程位置」，像浏览本地文件夹一样浏览里面的 `.omy` 文件，并**直接点播视频、预览图片，全程只传密文、在本机解密**。

目前支持两类远程位置：**WebDAV** 与 **Telegram**。

WebDAV 是绝大多数自建 NAS（群晖、威联通、TrueNAS）与聚合盘（AList、Nextcloud、ownCloud、可道云等）共同支持的标准协议，接一个 WebDAV 就覆盖了一大类存储，不必为每一家网盘单独适配。

Telegram 则把你的私聊、群组、频道当成目录来用——详见下面的 [Telegram](#telegram)。

::: tip 为什么从 WebDAV 开始
WebDAV 是开放标准，列目录、带 `Range` 的随机读取、上传、删除、改名都有统一语义。私有网盘（各家的开放平台）客户端差异大、令牌策略各不相同，留到确有需求时再按驱动逐个接入。
:::

## 添加一个远程位置

在图形界面里打开「连接远程位置」，填写：

- **服务器地址**：WebDAV 根 URL，例如 `https://nas.example.com/dav/`；
- **账号 / 密码**：该服务的登录凭据；
- **名称**：在侧栏里显示的名字，可留空自动取；
- **是否可写**：不确定就保持只读。

应用会先做一次只读探测：连得上、列得出目录才会把位置加进来；如果账号对该目录没有写权限，会自动判定为**只读位置**。

## 浏览、识别与点播

进入位置后，应用会列出目录内容并识别 `.omy` 文件：

- 识别时会读取文件头部，而不是只看文件名，因此改名、移动过的文件也能正确判断解锁状态；
- 视频、音频、图片走和本地一致的预览/播放链路，拖动进度条时按 HTTP `Range` 按需拉取密文块，**不会先把整个文件下载下来**；
- 网格视图下，已解锁且文件头带缩略图的条目直接显示缩略图。缩略图就在文件头 TLV 里，列目录读头部时顺带取得，**不产生正文下载**，失败时回退为类型图标；
- 目录采用**边扫边出**：列完目录先显示「识别中…」骨架，随后识别完一个就就地更新一个，不必等所有文件都读完；
- 个别文件因网络问题读不到头部时，会单独标成「未能读取」，**点一下该条目即可重试**，不会和「密码不对（锁定）」混为一谈，也不用刷新整个目录；
- 底部状态栏除了项目数，还会分别统计当前目录里 🔓 已解锁、🔒 尚未解锁（密码不对或还没试）的加密文件数，数字随边扫边出实时更新，识别中的条目暂不计入；
- 解密发生在本机，服务器和通道上始终只有密文——和[局域网共享](lan-sharing)的安全模型一致，你必须自己知道密码。

## Android：交给其他应用打开 WebDAV 文件

Android 上打开 WebDAV 文件的预览面板提供两个明确入口：

- **只读打开**：通过 `content://` URI 只向用户选中的应用授予读取权限；如果这个稳定 URI 以前曾以可编辑方式打开，本次会先撤销旧的写权限。
- **可编辑打开**：只在可写 WebDAV 位置显示，通过同一个 URI 向用户选中的应用授予读写权限。第三方应用是否真的支持原地保存仍取决于它自身。

同一远端文件始终映射到同一个应用私有路径，因此 URI 在反复打开和应用重启后保持稳定。URI 只允许访问本次外部打开所用的工作文件，不能借此浏览应用的状态文件、其他缓存或手机存储。

普通文件的授权直接绑定到选中的应用包，不依赖 omy 的界面或进程继续存活：外部应用结束接收页面后，仍可重新打开同一 URI；若 omy 被系统回收，Android 会按需拉起 FileProvider 提供文件。每次重新选择打开应用时，omy 会先撤销该 URI 的旧授权，只保留最后选中的应用和本次选择的只读/读写范围。此授权不是跨设备重启的永久授权——重启手机后需要从 omy 再打开一次；强行停止、清除数据或卸载 omy 也不在保证范围内。

加密文件不同：外部应用拿到的是解密后的明文工作副本，只授予随接收页面生命周期存在的临时权限；锁定 omy 时会立即撤销该 URI 的读写权限。已经打开的文件描述符受 Android 内核语义限制，无法从提供方强制收回，因此锁定前已由第三方应用打开的文件应先在该应用中关闭。

::: warning 外部打开会保存明文工作副本
内嵌预览使用 `omystream://`，明文不写盘；第三方应用无法使用这条内部协议。外部打开因此会把单个文件的**明文工作副本**保存到 omy 的 Android 私有目录。只有被选中的应用能凭临时授权访问它，但能以本机同一用户身份运行、设备已 root，或能读取应用私有数据的攻击者仍可能取得该副本。卸载或清除 omy 数据会删除它。
:::

可编辑文件不会在每次 `FileObserver` 事件后立即上传：观察器只标记“可能已修改”，omy 回到前台时立即检查，进程存活期间每 30 秒批量同步。即使系统杀掉 omy，编辑会话、版本基线和本地内容指纹也会持久保存；下次启动会重新检查并继续处理未同步修改。

同步不是盲目覆盖：打开时记录服务端的 ETag，服务端没有 ETag 时退回 Last-Modified；两者都不给时拒绝“可编辑打开”。上传使用条件写，若另一台设备已修改远端文件，omy 会保留本地修改并报告冲突，不会静默覆盖远端版本。

`.omy` 文件交给第三方的是解密后的单文件工作副本。同步回远端时会重新加密，并保留原文件 UUID、全部密码槽、设备密钥槽、恢复码槽和格式参数；加密目录容器不支持外部编辑。为覆盖“上传已成功但状态尚未落盘就被系统杀掉”的窗口，待上传密文会先作为事务文件持久化，重启后复用同一份字节确认结果。

## 只读位置能做什么、不能做什么

能力由后端按真实探测结果决定，而不是界面上的开关：

| 操作 | 可写位置 | 只读位置 |
|---|---|---|
| 列目录、识别 `.omy` | ✅ | ✅ |
| 预览 / 点播（按需读密文） | ✅ | ✅ |
| 列表缩略图（读文件头，不读正文） | ✅ | ✅ |
| 解密到本地（明文只落在本机） | ✅ | ✅ |
| 密文块缓存 | ✅ | ✅ |
| 从缓存移除单个文件（只清本机密文） | ✅ | ✅ |
| 加密后上传 / 上传至其他远程 | ✅ | ❌ 发请求前即拒绝 |
| 转为永久保留 / 取消 | ✅ | ✅ |
| 新建文件夹、改名、删除 | 尚未提供 | ❌ |

在条目上 **桌面右键、移动端长按** 会弹出条目菜单：「预览 / 打开」、「上传至…」、「解密到本地…」、「转为永久保留」（已永久保留的显示为「取消永久保留」），以及在该文件确有本地密文缓存时才出现的「从缓存中移除」。

菜单项按**当前目录**的真实能力出现，而不是按位置。同一个 Telegram 位置里，对话列表那层不可写、只读频道不可写、你自己的群可写——所以上传按钮只在能写的地方出现。

### 解密到本地

只读位置改不了远端，却仍然需要把某个文件拿回本机编辑或长期保存——这正是「解密到本地」的用途：服务器上始终只有密文，明文只在你选的本地文件夹里生成。

- 选择一个本地文件夹后，应用**流式**拉取密文、解密、逐段写盘，几个 GB 的视频也不会整份读进内存；
- 下载同样走密文块缓存，拖动预览过的部分不重复下载；
- 文件名取自加密文件头里记录的原始名（并做路径清洗，防止构造的文件名写出目标目录），**默认不覆盖**：目标已有同名文件会直接报错，让你换个位置；
- 加密文件夹（容器）暂不支持远程解密到本地，请先在本地处理。

加密上传已经可用（见下面 Telegram 一节）。删除、改名、新建文件夹当前版本仍不提供通用入口；「上传至」会在内部按目标能力使用它们完成安全收尾，详见下一节。

### 上传至其他远程位置

本地文件或真实远程位置里的文件都可以通过条目右键菜单选择 **「上传至…」**。目标选择器可逐级浏览 WebDAV 文件夹或 Telegram 对话，并且每进入一个目录都会重新查询该目录的有效能力；只有 `write` 为真时才能确认，不会把位置级“最多可写”误当成当前目录真的可写。

- **本地 → 远程**：沿用普通上传，直接从本地文件读取；
- **远程 → 远程（缓存到本地并上传）**：下载到的密文块进入永久缓存，上传失败后重试会复用已有分块，代价是占用本地磁盘；
- **远程 → 远程（内存中上传）**：源端每次读取最多 8 MiB，下载与上传之间使用固定 64 MiB 的有界内存队列，不写本地文件；上传较慢时下载会自动等待，不会无限积压。

目标端的收尾策略同样由能力决定，而不是假定所有远程都支持改名或删除：

1. 目标同时支持写入、重命名和删除时，先写入随机临时名，成功后改成最终名；失败时可精确删除临时对象；
2. 缺少重命名或删除任一能力时，直接写最终文件名；如果支持删除，失败时尽力清理；不支持删除或清理失败时，传输页会明确提示“目标可能保留不完整文件”，并停止提供重试按钮，要求先去目标位置处理；
3. 对路径型目标（如 WebDAV），开始前发现同名文件会拒绝覆盖。

两种远程复制任务都会立即进入**传输管理**页，可查看进度、取消和对可重试失败执行重试。

#### Telegram 能否续传

需要区分下载和上传：

- **下载支持按偏移继续读取**。Telegram 的下载接口接受 `offset`，永久缓存模式重试时会直接命中已经下载的分块，不重复拉取；
- **上传协议本身是分片的，但当前 omy 不能在整条任务失败后从服务端已收分片继续**。当前使用的 grammers 上传接口每次调用都会生成新的 `file_id`，且不向调用方暴露已完成分片集合，因此重试 Telegram 上传必须从头上传；这些临时上传分片在服务端也只短期有效；
- 内存模式不保存源分块，所以任务失败后源端也重新读取；永久缓存模式可省掉重复下载，但目标上传仍从头开始。

## Telegram

把你的 Telegram 对话挂成远程位置：**每个对话是一个目录**，里面的文件、图片、视频就是这个目录下的条目。`.omy` 文件和在 WebDAV 上一样能识别、预览、点播。

### 登录

在侧栏点 Telegram 图标，有两条路：

- **扫码登录**：用已经登录的手机扫一下，不必把手机号和验证码输进 omy。二维码会在过期时自动换新，界面上能看出它刷新了。如果你的账号开了两步验证，会在需要时单独问你云密码——没开的话不会出现这一步。
- **复用桌面端登录态**：读取本机 Telegram Desktop 的 `tdata`，直接用它已有的登录，不用扫码。需要先**退出**桌面客户端（关窗口不够，它会最小化到托盘）。便携版的 `tdata` 在 `Telegram.exe` 同目录，自动探测通常找不到，界面会让你手动指定。

::: warning 复用桌面端登录态 = 共用同一份会话
导入之后 omy 与桌面客户端**共用一份登录会话**，不是两份：桌面端登出时，omy 这边会一并失效。
:::

登录态（含账号凭据）加密后保存在本机。密钥交给系统凭据库；**拿不到凭据库时不会退回明文保存**，代价是每次启动都要重新登录。

**默认不加密，加密是可选的。** 不设 omy 密码的账号保持原样，连上后照常自动连接。想给某个保密账号加一层 omy 密码保护时，有两个入口：

- **侧栏右键 →「加密此位置」**：弹出密码对话框，**当场设一个密码**（输两次确认，可选 KDF 强度），和加密普通 omy 文件是同一套交互；右键菜单里也能「取消加密」转回默认。
- **添加账号成功后**会问一次「要不要加密」，可加密、也可跳过（默认不加密）。

加密的钥匙就是你设的这个密码。它与普通 .omy 文件、其它加密位置走**同一个会话密码池**：
omy 会记住每次见过的加密库（只记文件头里公开的盐与 Argon2 参数，不存密码），所以只要密码
相同，无论先解锁本地文件还是先解锁某个位置，其余同密码的库与 Telegram 位置都会自动解锁，
不必重输，右上角的「N 个密码已解锁」也只按不同密码计数。

**加密之后**：这个位置显示为已加密（带锁标识）。冷启动、还没输密码时它显示**锁定**——能看到名称、进不去，提示先解锁；输对密码后即可进入并自动连接。名称在锁定态下始终可见。**没加密的位置不受影响**，照常直接进入。

::: tip 大多数网络下需要代理
直连 Telegram 数据中心在很多网络里不通。登录界面可以填代理地址，形如 `socks5://127.0.0.1:7897`；填 `http://` 形式时会按同端口的 SOCKS5 自动尝试。打开登录界面时，omy 会优先推荐已有 Telegram 位置验证过的代理，没有时才采用系统代理；主动点击「读取系统代理」则只读取此刻的系统设置，不会复用旧位置保存的端口。代理设置会随位置一起保存。
:::

omy 在 Telegram 的「已登录设备」列表里 **如实显示为 omy**，不伪装成官方客户端——你随时可以在官方客户端里认出它并撤销。

### 多个账号

可以同时挂多个 Telegram 账号，每个账号是一个独立的远程位置，各自保存自己的登录态。已经加过一个账号之后再点添加，仍然会走一次完整登录，而不是直接复用现有账号。

位置名默认取自该账号的昵称。两个账号昵称相同时（比如同一个人的大小号）光看侧栏分不清，所以位置名 **可以改**：在位置列表里点该行的 ✎。改的只是它在本机的显示名，不会动服务端的账号资料。

移除一个 Telegram 位置有两种，后果差得很远，界面上是两个入口：

| | 登录态 | 下次再用 |
|---|---|---|
| **从列表移除**（✕） | 保留在本机 | 直接加回来，不用重新扫码 |
| **删除账号**（🗑️） | 一并删除 | 需要重新扫码或重新导入 tdata |

后者不可撤销，点之前会写明后果。另外要注意：**从列表移除不会删掉已经转为永久保留的文件**，它们仍占着磁盘，要清理请去设置里的永久保留清单。

### 浏览与搜索

进入位置后先看到对话列表，点进某个对话就是它的文件列表。文件列表按类型分成**媒体、文件、链接、音频、GIF** 五个分栏，各由 Telegram 服务端按类型索引返回：媒体栏放图片和视频，文件栏放文档，其余各自成栏。作为照片发送的图片和作为视频发送的视频落在媒体栏，作为文件发送的文档落在文件栏。分栏逐屏加载——先填满一屏，往下滚再取下一批。缩略图先显示随消息带回的极低清占位图，清晰图在后台取到后自动替换。

对话里还有一个**消息视图**，以文件为主线地把消息按时间列出来，带文件的消息可以直接点开。广播频道的消息视图是**只读浏览**（能看，但 omy 不实现赞助消息，原因见下面的说明）。

消息上带着「回复 #N」引用时，点它会跳到被引用的那条：加载期间只在引用旁转一个小圈、不会刷新整个列表；被引用消息不在已加载范围内时，会以它为中心拉一段并高亮。跳转之后时间线**两头都能继续翻**——向下翻更旧的消息，向上（顶部）翻回更新的消息，跳转前的消息不会丢。

消息里的文件块：单击直接**预览/打开**；右键选「在文件中显示」则切到对应的文件分栏（照片视频 / 文档 / 链接 / 音乐 / GIF，按文件类型自动判断），把那张文件卡片滚动到中间并高亮。目标不在当前已加载范围时，会以它为锚点拉一页，不会触发连续翻页。

### 多选与转发

Telegram 对话里的文件和消息都可以原生转发：

- 文件视图中，单个文件可在右键菜单选择 **「转发…」**；桌面用 Ctrl/⌘ 点击、移动端长按进入多选后，工具条也会出现 **「转发」**；
- 消息视图中，每条消息左侧有复选框，可选择纯文本消息或带文件的消息；消息行右键也能直接转发单条；
- 目标弹窗只列当前 Telegram 账号下**实际有写权限的群组或个人**，不列只读会话和广播频道；可以按名称搜索；
- 转发使用 Telegram 原生 `forwardMessages`，由服务端直接转发消息，**不会先下载文件再重新上传**；消息按原时间顺序发送，并对重复选择去重；
- 单次最多转发 100 条，使一次操作只对应一个服务端请求，避免分批成功一半后无法安全重试；
- 可以在目标弹窗中**新建一个初始成员只有自己的超级群**。创建完成后会选中新群，但仍需再次点击「转发到这里」，不会因建群自动发送；
- 转发仅限同一个 Telegram 账号内；开启「受保护内容」的源对话不能转发，omy 会在发请求前提示。

搜索分两种，界面上分得很清楚：

- **本地过滤**：只在已经列出来的条目里筛，搜索词不发给任何人；
- **服务端搜索**：由 Telegram 在服务端搜，能搜到没列出来的历史消息。**这会把你的搜索词发给 Telegram**，所以需要你显式切换，并且切换后界面上有一条提示条写明发出去的是哪个词。

在对话列表这一层做服务端搜索，会跨所有对话搜；没有权限的对话自动跳过，但被限流或网络出错时会照实告诉你——那和「真的没搜到」是两回事。

### 上传

往可写的对话里上传文件时，omy 一律作为**文件**发送，而不让客户端按内容自动判别（即不走「作为照片发送」那条路）。作为照片发送时服务端会重新编码，对密文是毁灭性的，而失败症状会指向密钥而不是上传方式。

### 当前限制

- 部分群组开启了「限制保存内容」（`noforwards`）。omy 仍然能正常读取和播放这些文件，但**不能转发**它们；转发入口会禁用，后端也会在发请求前再次拒绝。
- 极少数文件会被服务端要求走 CDN 重定向，当前版本不支持这条路径，会明确报错而不是静默失败。
- **广播频道的消息视图是只读的，omy 不实现赞助消息**。Telegram 的服务条款要求展示消息流的客户端支持并如实展示赞助消息（广告），而一个本地加密文件管理工具去承接广告投放与曝光回报，与 omy 的定位冲突。omy 的取舍是：**只读浏览频道消息、不实现赞助消息**（即不参与广告分发），而不是干脆连消息都不给看。频道里的**文件与媒体分栏照常可用**。

## 密文缓存

远程文件反复拖动播放会重复拉取同样的密文。应用在本地维护一个**只存密文**的块缓存：

- 缓存块按 1 MiB 对齐，采用 LRU 淘汰，用量超过上限时淘汰最久未用的块；
- **绝不缓存明文或密钥**，缓存目录即使被整个拷走也只是密文；
- 缓存键包含文件头部与总长度，因此同名文件内容更新后不会错误命中旧缓存。

在「设置 → 远程位置 → 密文缓存」里可以：

- 设置最大缓存（512 MB / 1 GB / 2 GB / 5 GB / 10 GB / 不限），默认 2 GB；
- 查看当前已用空间、立即清空；
- 打开缓存所在目录；
- 选择退出应用时自动清空。

除了在设置里整体清空，也可以只清理某一个文件：在条目菜单里选「从缓存中移除」，只删除该文件下载到本机的密文块，不碰云端文件，因此只读位置也能使用。菜单是按需查询的——只有该文件确实缓存了部分密文块时这一项才会出现，没有缓存的文件不会显示一个空操作。是否完整缓存（可离线播放）按 1 MiB 块逐块统计，不在列目录时对每个文件做扫描，以免文件很多时拖慢浏览。

### 永久保留

上面那个缓存是会被淘汰的：空间紧张时最久未用的块先被清掉。如果某个文件你想确保离线也能打开，在它的条目菜单里选「转为永久保留」。

- 永久保留的文件 **不计入上面的缓存上限，也不参与淘汰**，所以设置里这两个数字是分开显示的：临时缓存给「已用 / 上限」，永久保留只给占用大小和文件数——它没有上限，画一根进度条反而会让人去找那个不存在的分母；
- 转为永久保留是一次真实的下载：它会把整个文件的密文取全，而不只是标记一下。只打标记的话「永久」只是个承诺，下次离线打开照样失败；
- 取消永久保留会直接把这些密文块删掉、把空间还回来。

在「设置 → 远程位置 → 密文缓存 → 管理永久保留…」里可以看到所有永久保留的文件并逐个取消。没有这个入口的话，你只能回到文件原来所在的位置、在目录里把它找出来再右键——而 Telegram 上那条消息可能早就翻不到了。

这个清单在 **位置已经被移除之后仍然有效**：那一行会显示成「已移除的位置」，但照样能点取消、把空间清出来。

「仅在 Wi-Fi 下缓存」在移动端将在后续版本提供。

## 配置与缓存放在哪

遵循便携优先：

- **桌面端**：配置文件 `omy-data/config.toml` 与缓存目录 `omy-data/cache/remote/` 都在可执行文件旁边，拷走整个目录即可带走设置与缓存；
- **移动端**：放在应用自己的数据目录。

配置项的完整字段见[配置文件](configuration)。

## 密码怎么保存

远程位置会随配置一起保存，重启后自动恢复。**密码不会明文写进配置文件**：
它先被一把密钥加密，而那把密钥交给操作系统保管。

| 平台 | 保管处 |
|---|---|
| Windows | 凭据管理器 |
| macOS | 钥匙串 |
| Linux | Secret Service（gnome-keyring / KWallet 等） |
| Android | 应用私有目录 |

这意味着**配置文件被拷到另一台机器上也用不了**——那里没有这把密钥。
同样，你自己换了电脑、或清空过钥匙串，位置还会列出来，但需要重新输一次密码。

::: warning 它挡什么、不挡什么
挡得住的是：配置文件被拷走、硬盘被取下来挂到别的机器、备份泄露。

**挡不住**能以你的身份在这台机器上运行程序的攻击者——他可以直接问系统要
这把密钥。这是操作系统凭据库的固有边界，不是 omy 特有的限制。真要防这个，
需要「每次解锁都验证指纹」这一档，目前还没有。
:::

::: tip Linux 需要一个钥匙串服务
Linux 上必须有实现了 Secret Service 的服务（装了桌面环境通常就有）。
没有的话 omy **不会**退回明文保存——位置照样保存，但密码不存，每次启动
需要重新输入。设置里会显示当前是哪种状态。

内核 keyring（keyutils）虽然也能用，但它重启就清空，等于每次开机都要重输，
所以 omy 不用它。
:::

::: warning Windows：凭据管理器可能被别的程序占满
如果设置里显示「无法安全保存密码」，而你用的是 Windows，多半是凭据管理器
已经满了——某些程序（实测见过 VS Code 的微软账号令牌）会不断累积凭据而从不
清理，攒到几百条就再也写不进新的。

先看是谁占的：

```powershell
(cmdkey /list | Out-String) -split "`r?`n" |
  Where-Object { $_ -match 'Target:' } |
  ForEach-Object { ($_ -replace '.*Target:\s*','') -split '[|:/]' | Select-Object -First 1 } |
  Group-Object | Sort-Object Count -Descending | Select-Object -First 5
```

确认某一类可以安全删除后（登录令牌删掉只需重新登录一次，不会丢数据），
按关键词清理：

```powershell
(cmdkey /list | Out-String) -split "`r?`n" |
  Where-Object { $_ -match '关键词' } |
  ForEach-Object { (($_ -replace '.*Target:\s*','').Trim()) -replace '^LegacyGeneric:target=','' } |
  ForEach-Object { cmdkey /delete:$_ }
```

目标名要去掉 `LegacyGeneric:target=` 前缀，带着前缀删会报「找不到元素」。
:::

配置文件里的**名字、地址、用户名是明文的**，只有密码加密。这是有意的：
没有密钥时也要能列出这些位置告诉你「需要重新登录」，而不是显示一片空白
让人以为配置丢了。代价是看到配置文件的人能知道你在用哪个服务器。

## 虚拟远程位置（收藏夹）

「远程」区里可以新建**虚拟远程位置**：它不连任何服务器，只收集你从真实远程
（Telegram / WebDAV）里选出的文件的**引用**，用来跨账号、跨对话地整理常看的东西。

- **新建**：侧栏「远程」区点「新建虚拟远程」，起个名字即可。
- **加内容**：在真实远程里右键一个文件（或选中多个）→「添加到虚拟远程…」。
  对话框里点某个虚拟远程的名字就是加到它的**根目录**（文件可以直接放根，不必先
  建文件夹）；点右侧箭头展开后可选到某个具体子文件夹。
- **整理**：进入虚拟位置后，顶部有「新建文件夹 / 粘贴」；右键引用或文件夹可以
  新建、重命名、删除，以及**剪切 / 复制 / 粘贴**（也支持 Ctrl+X / Ctrl+C /
  Ctrl+V、Delete）。剪切、复制只在**虚拟位置之间**粘贴——真实远程不接受引用；
  剪切是同位置移动，复制与跨位置粘贴会生成新引用。删除只移除收藏指针，**不会**
  删除真实文件。**不能直接往虚拟位置上传文件**——它只存引用。
- **多选**：桌面按住 Ctrl（Mac 为 ⌘）点条目逐个勾选，或在勾选态下直接点；
  手机上**长按**条目进入多选（本地文件列表也支持长按多选）。勾选后顶部出现批量
  「剪切 / 复制 / 删除」条，也支持 Ctrl+X / Ctrl+C / Delete。
- **侧栏管理**：在侧栏的虚拟位置上**右键**，可以编辑（重命名）、删除，以及
  **加密 / 解锁 / 锁定**。加密的是「这份收藏指向了哪些文件」本身（名字仍显示），
  用独立密码 + Argon2 加密落盘；锁定后内存里不留明文，重新进入要输密码。虚拟位置
  的密码与普通 .omy 文件的密码是**同一个会话密码池**：用相同密码时，解锁其中一边，
  另一边会自动解锁，右上角的「N 个密码已解锁」也会计数。omy 会记住每次浏览、扫描时
  见过的加密库（只记文件头里公开的盐与 Argon2 参数，不存密码），所以只要这个库曾在
  任意位置出现过，之后用相同密码解锁任一处，它都会一起解锁——不必当时正停在那个目录。
- **打开**：双击一条引用会**原地预览/播放**它指向的真实文件（委托源读取，不
  切走当前虚拟位置）；真实位置已经缓存过的内容**直接秒开**（引用和真实文件共用
  同一份缓存，不会重复下载）。
- **定位来源**：右键一条引用——
  - Telegram 文件给两个入口：「定位到源消息」（跳到那个对话的消息时间线并高亮
    那条消息）和「定位到源文件」（切到该文件所在的分栏，把文件卡片滚出来高亮；
    文件类型在添加引用时就已记住）；
  - WebDAV 等非 Telegram 源只有「定位到真实位置」一项，等同于直接进到源目录
    里那个文件。
- **来源变化**：引用记的是账号的稳定标识（不是会变的本地编号）。所以你把某个
  远程从列表里移除、之后又加回来，引用会自动重新认上、恢复可用；来源暂时不在
  时引用不会消失，会标成「来源不可用」；来源加密还没解锁时会提示你先去解锁。

## 当前限制（首期）

- 新建文件夹、改名 / 删除尚未提供（加密后上传已经可用）；加密文件夹（容器）暂不支持远程解密到本地。
- 暂未接入 WebDAV 与 Telegram 之外的私有网盘驱动。
- 暂不支持「用指纹 / 面容解锁」这一档凭据保护。
