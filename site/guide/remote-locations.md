# 远程位置（云盘 / WebDAV）

把 NAS、网盘或任何支持 WebDAV 的服务挂成一个「远程位置」，像浏览本地文件夹一样浏览里面的 `.omy` 文件，并**直接点播视频、预览图片，全程只传密文、在本机解密**。

首期支持的协议是 **WebDAV**。它是绝大多数自建 NAS（群晖、威联通、TrueNAS）与聚合盘（AList、Nextcloud、ownCloud、可道云等）共同支持的标准协议，接一个 WebDAV 就覆盖了一大类存储，不必为每一家网盘单独适配。

::: tip 为什么从 WebDAV 开始
WebDAV 是开放标准，列目录、带 `Range` 的随机读取、上传、删除、改名都有统一语义。私有网盘（各家的开放平台）客户端差异大、令牌策略各不相同，留到确有需求时再按驱动逐个接入。
:::

## 添加一个远程位置

在图形界面里打开「连接远程位置」，填写：

- **服务器地址**：WebDAV 根 URL，例如 `https://nas.example.com/dav/`；
- **账号 / 密码**：该服务的登录凭据；
- **名称**：在侧栏里显示的名字，可留空自动取；
- **是否可写**：不确定就保持只读。

应用会先做一次只读探测：连得上、列得出目录才会把位置加进来；如果账号对该目录没有写权限，会自动判定为**只读位置**。

## 浏览、识别与点播

进入位置后，应用会列出目录内容并识别 `.omy` 文件：

- 识别时会读取文件头部，而不是只看文件名，因此改名、移动过的文件也能正确判断解锁状态；
- 视频、音频、图片走和本地一致的预览/播放链路，拖动进度条时按 HTTP `Range` 按需拉取密文块，**不会先把整个文件下载下来**；
- 网格视图下，已解锁且文件头带缩略图的条目直接显示缩略图。缩略图就在文件头 TLV 里，列目录读头部时顺带取得，**不产生正文下载**，失败时回退为类型图标；
- 目录采用**边扫边出**：列完目录先显示「识别中…」骨架，随后识别完一个就就地更新一个，不必等所有文件都读完；
- 个别文件因网络问题读不到头部时，会单独标成「未能读取」，**点一下该条目即可重试**，不会和「密码不对（锁定）」混为一谈，也不用刷新整个目录；
- 底部状态栏除了项目数，还会分别统计当前目录里 🔓 已解锁、🔒 尚未解锁（密码不对或还没试）的加密文件数，数字随边扫边出实时更新，识别中的条目暂不计入；
- 解密发生在本机，服务器和通道上始终只有密文——和[局域网共享](lan-sharing)的安全模型一致，你必须自己知道密码。

## 只读位置能做什么、不能做什么

能力由后端按真实探测结果决定，而不是界面上的开关：

| 操作 | 可写位置 | 只读位置 |
|---|---|---|
| 列目录、识别 `.omy` | ✅ | ✅ |
| 预览 / 点播（按需读密文） | ✅ | ✅ |
| 列表缩略图（读文件头，不读正文） | ✅ | ✅ |
| 解密到本地（明文只落在本机） | ✅ | ✅ |
| 密文块缓存 | ✅ | ✅ |
| 从缓存移除单个文件（只清本机密文） | ✅ | ✅ |
| 加密后上传、新建文件夹、改名、删除 | ✅（规划中） | ❌ 发请求前即拒绝 |

在条目上**桌面右键、移动端长按**会弹出条目菜单，首期提供「预览 / 打开」「解密到本地…」，以及在该文件确有本地密文缓存时出现的「从缓存中移除」。

### 解密到本地

只读位置改不了远端，却仍然需要把某个文件拿回本机编辑或长期保存——这正是「解密到本地」的用途：服务器上始终只有密文，明文只在你选的本地文件夹里生成。

- 选择一个本地文件夹后，应用**流式**拉取密文、解密、逐段写盘，几个 GB 的视频也不会整份读进内存；
- 下载同样走密文块缓存，拖动预览过的部分不重复下载；
- 文件名取自加密文件头里记录的原始名（并做路径清洗，防止构造的文件名写出目标目录），**默认不覆盖**：目标已有同名文件会直接报错，让你换个位置；
- 加密文件夹（容器）暂不支持远程解密到本地，请先在本地处理。

需要改写远端的操作（加密上传、删除、改名、新建文件夹）当前版本尚不提供入口；后续加入时，会在只读位置**整项隐藏而非置灰**，对「位置能写但不支持原地改写」的情形再置灰并在菜单项下方说明「云端不支持原地改写，请先解密到本地」，避免在一个写不进去的目录里走到一半才失败。

## 密文缓存

远程文件反复拖动播放会重复拉取同样的密文。应用在本地维护一个**只存密文**的块缓存：

- 缓存块按 1 MiB 对齐，采用 LRU 淘汰，用量超过上限时淘汰最久未用的块；
- **绝不缓存明文或密钥**，缓存目录即使被整个拷走也只是密文；
- 缓存键包含文件头部与总长度，因此同名文件内容更新后不会错误命中旧缓存。

在「设置 → 远程位置 → 密文缓存」里可以：

- 设置最大缓存（512 MB / 1 GB / 2 GB / 5 GB / 10 GB / 不限），默认 2 GB；
- 查看当前已用空间、立即清空；
- 打开缓存所在目录；
- 选择退出应用时自动清空。

除了在设置里整体清空，也可以只清理某一个文件：在条目菜单里选「从缓存中移除」，只删除该文件下载到本机的密文块，不碰云端文件，因此只读位置也能使用。菜单是按需查询的——只有该文件确实缓存了部分密文块时这一项才会出现，没有缓存的文件不会显示一个空操作。是否完整缓存（可离线播放）按 1 MiB 块逐块统计，不在列目录时对每个文件做扫描，以免文件很多时拖慢浏览。

「仅在 Wi-Fi 下缓存」在移动端将在后续版本提供。

## 配置与缓存放在哪

遵循便携优先：

- **桌面端**：配置文件 `omy-data/config.toml` 与缓存目录 `omy-data/cache/remote/` 都在可执行文件旁边，拷走整个目录即可带走设置与缓存；
- **移动端**：放在应用自己的数据目录。

配置项的完整字段见[配置文件](configuration)。

## 密码怎么保存

远程位置会随配置一起保存，重启后自动恢复。**密码不会明文写进配置文件**：
它先被一把密钥加密，而那把密钥交给操作系统保管。

| 平台 | 保管处 |
|---|---|
| Windows | 凭据管理器 |
| macOS | 钥匙串 |
| Linux | Secret Service（gnome-keyring / KWallet 等） |
| Android | 应用私有目录 |

这意味着**配置文件被拷到另一台机器上也用不了**——那里没有这把密钥。
同样，你自己换了电脑、或清空过钥匙串，位置还会列出来，但需要重新输一次密码。

::: warning 它挡什么、不挡什么
挡得住的是：配置文件被拷走、硬盘被取下来挂到别的机器、备份泄露。

**挡不住**能以你的身份在这台机器上运行程序的攻击者——他可以直接问系统要
这把密钥。这是操作系统凭据库的固有边界，不是 omy 特有的限制。真要防这个，
需要「每次解锁都验证指纹」这一档，目前还没有。
:::

::: tip Linux 需要一个钥匙串服务
Linux 上必须有实现了 Secret Service 的服务（装了桌面环境通常就有）。
没有的话 omy **不会**退回明文保存——位置照样保存，但密码不存，每次启动
需要重新输入。设置里会显示当前是哪种状态。

内核 keyring（keyutils）虽然也能用，但它重启就清空，等于每次开机都要重输，
所以 omy 不用它。
:::

配置文件里的**名字、地址、用户名是明文的**，只有密码加密。这是有意的：
没有密钥时也要能列出这些位置告诉你「需要重新登录」，而不是显示一片空白
让人以为配置丢了。代价是看到配置文件的人能知道你在用哪个服务器。

## 当前限制（首期）

- 加密后**上传**、新建文件夹、改名 / 删除、传输进度等**远端写操作**尚未提供，当前版本面向「远程浏览、点播与解密到本地」；加密文件夹（容器）暂不支持远程解密到本地。
- 暂未接入 WebDAV 之外的私有网盘驱动。
- 暂不支持「用指纹 / 面容解锁」这一档凭据保护。

这些项的设计与进展记录在仓库的 `docs/research/14-remote-locations-cloud.md`。
