# 密码与密钥槽

## 密码怎么输入

按推荐程度排序：

| 方式 | 参数 | 说明 |
|---|---|---|
| 交互式（默认） | 无 | 不回显，不进 history |
| 标准输入 | `--password-stdin` | 适合 CI 的 secret |
| 文件 | `--password-file <路径>` | 读首行，建议 `chmod 600` |
| 环境变量 | `--password-env <变量名>` | 传变量**名**而非值 |

**不存在 `--password <明文>` 这个参数。** 试着用它会得到明确的说明和退出码 2：

```
不支持 --password 参数

  命令行参数对同机其它用户可见（ps aux / 任务管理器），
  且会被记入 shell 历史文件。

  请改用：
    --password-stdin        从管道读取
    --password-file <路径>  从文件读取
    --password-env <变量名> 从环境变量读取（传变量名，不是值）
    （不带任何参数）        交互式输入，不回显
```

::: warning 环境变量也不是完全安全的
`--password-env` 传的是变量名，避免了参数可见的问题，但环境变量本身在部分系统上可通过 `/proc/<pid>/environ` 读到。CI 里优先用 `--password-stdin`。
:::

## 一个文件挂多个密码

每个 `.omy` 有 **8 个密钥槽**。每个槽独立包裹同一个文件密钥（FEK），所以任一密码都能单独解开文件，彼此不需要知道对方。

加密时就配多个：

```bash
omy encrypt --add-password --add-password file.mp4
```

`--add-password` 可重复，每次多要一个密码（只支持交互式输入，避免多个密码从同一个非交互源读串）。加上主密码，最多 8 个。

事后追加：

```bash
omy key add file.omy
```

需要先提供一个已有密码（证明你有权限），再输入要新增的那个。

## 看槽位占用情况

```bash
omy key list file.omy
```

```
文件        note.txt.omy
Slot 总数   8
Slot 占用   未知（设计上不可探测）

slot 区始终填满，真实 slot 与随机填充在字节层面无法区分。
这是可否认性设计的基础：无法判断该文件配置了几个密码。
```

::: tip 这不是功能缺失
「看不出配了几个密码」是刻意设计。空槽填的是随机字节，与真实槽在字节层面无法区分。所以旁人拿到文件也无法判断它有几个密码、是否存在你不愿承认的第二个密码。

代价是你自己也查不了——需要自己记住配过哪些密码。
:::

注意 `key list` **不接受密码参数**：既然槽位占用本来就不可探测，给它密码也没有额外信息可显示。

## 改密码

```bash
omy key change file.omy      # 旧密码作废，换成新的
omy key remove file.omy      # 只保留当前密码，作废其它所有密码
```

`change` 只重新包裹 FEK，**不重新加密载荷**，所以无论文件多大都是瞬间完成。

这也意味着：**文件密钥没有变**。如果你担心旧密码已经泄露、且对方可能已经从文件里提取出了 FEK，改密码是不够的——需要换掉 FEK：

```bash
omy key reencrypt file.omy
```

这会生成新的文件密钥并重写整个载荷（可以同时改密码）。大文件上这一步耗时与重新加密相当。

| 场景 | 用哪个 |
|---|---|
| 密码想换个好记的 | `key change` |
| 不想让某个协作者继续访问 | `key remove` |
| 怀疑密码泄露且文件可能已被拷走 | `key reencrypt` |

## 库（vault）与 salt

同一个「库」共享一个 vault salt 与 KDF 参数。同库的文件用同一个密码时，Argon2 只需跑一次，扫描整个目录很快。

不指定 `--vault` 时每次加密都生成新 salt，文件各自成库——即使密码相同，扫描时也要为每个库单独跑一次 Argon2（每次几十到几百毫秒，文件多了就很明显）。

```bash
# 加入已有库：指向该库的任一文件，或该库所在目录
omy encrypt --vault photos.omy new.jpg
omy encrypt --vault ./vault-dir/ new.jpg
```

## 多密码扫描

```bash
omy scan --password-file pw1.txt --password-file pw2.txt ~/Documents
```

`--password-file` 与 `--password-env` 都可重复。omy 对每个文件依次试所有密码，能解开的列出来（显示解密后的真实文件名）。

```bash
omy scan --show-locked .        # 连没解开的也列出来
omy scan --any-extension .      # 也检查后缀不是 .omy 的文件
omy scan --max-files 5000 .     # 限制单次扫描的文件数
```

`--any-extension` 会连后缀不是 `.omy` 的文件也读一次头部——识别靠的是文件头的 magic（`OMYFILE` + 版本字节），不是后缀。所以改过后缀的文件仍能被找到。

## 桌面端：一次装入多个密码

界面上的密码框是**累加**的，不是「换一个」。再输一个密码不会顶掉已经装入的：

1. 输入密码 A → 用 A 加密的那些文件显形
2. 再输入密码 B → A 的文件**仍然可见**，B 的文件一并显形

状态栏会显示当前装了几个密码。同一个密码重复输入只算一条（按密钥指纹判断，不看你给它起的名字），界面会提示「这个密码已经在用了」而不是假装添加成功。

这正是[可否认性](./security.md)在日常使用中的样子：真实密码与诱饵密码可以同时装着，各看各的文件，而从文件本身看不出任何一个库里配了几个密码。

按状态栏的 🔒 锁定时，所有密码一次性全部清除，不存在「只锁一半」。

::: tip 与「一个文件挂多个密码」的区别
上一节说的是**一个文件**能被几个密码打开（8 个密钥槽）。这一节说的是**一个会话**同时拿着几个密码去试。两者独立：你可以用三个密码浏览，而其中每个文件各自只挂一个密码。
:::

## 忘记密码

没有找回途径。设计上不存在后门、主密钥或恢复短语。

这不是疏漏：任何找回机制都是一条绕过密码的路径，也就是攻击面。请自行做好密码备份（密码管理器、离线纸质备份）。
