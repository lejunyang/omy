# omy 是什么

omy 是一个跨平台的加密文件管理工具。它要解决的是加密工具普遍存在的一个矛盾：

**加密之后文件就不好用了。** 想看一眼加密压缩包里的照片，得先整份解出来；想拖动播放一部加密的电影，要么等它全部解密落盘，要么放弃。解密出来的明文又留在磁盘上，等于白加密一次。

omy 的做法是把「能用」直接做进格式里。

## 它和常见方案的区别

| | 加密压缩包 | 加密容器 / 虚拟盘 | omy |
|---|---|---|---|
| 看一张图 | 解压整个包 | 挂载后正常读 | 只读文件头即可显示缩略图 |
| 拖动播放视频 | 先完整解压 | 可以，但需要挂载权限 | 直接 seek，不落盘 |
| 明文是否落盘 | 是 | 挂载期间对全系统可见 | 不落盘 |
| 需要管理员权限 | 否 | 通常需要 | 否 |
| 单文件独立可用 | 整包绑定 | 整个容器绑定 | 每个 `.omy` 自包含 |

加密容器的问题在于：挂载之后，整个卷对系统上的所有程序都是明文，粒度太粗。omy 的每个 `.omy` 文件是自包含的——搬走一个文件，它在别处照样能用同一个密码打开。

## 核心机制

**分块 AEAD。** 载荷按固定大小分块（默认 256 KiB），每块独立加密并带认证标签。要读第 100 秒的画面，只解密对应的那几块，这是任意 seek 能成立的前提。文件头里存着足够的信息，让块偏移的计算是 O(1) 的。

**自定义协议 + HTTP Range。** 图形界面里的播放器通过 `omystream://` 协议取数据，服务端按 Range 请求只解密并返回需要的区间。这条路径经过实测：6 次乱序 seek 全部落点准确，且 WebView 没有把解密后的数据写进磁盘缓存。

**两级密钥派生。** 密码先经 Argon2id 派生出 KEK，再由 HKDF 派生出各槽的包裹密钥；真正加密载荷的文件密钥（FEK）是随机生成的，被包裹后存在密钥槽里。改密码只需重新包裹 FEK，不必重新加密整个文件。

**缩略图在文件头内。** 加密时生成缩略图（图片缩放原图，视频抽帧），加密后存入文件头的 TLV 区。列表页只读头部就能显示，不必接触载荷。

## 两个入口，同一套核心

命令行（`omy`）与图形界面（`omy-gui`）都建立在 `omy-core` 之上，行为一致。CLI 面向脚本、服务器和批处理，提供 JSON 输出和精确的退出码；图形界面提供文件浏览、内嵌预览与播放。

它们操作的是同一种文件，可以互相接手：CLI 加密的文件在界面里能直接浏览播放，反之亦然。

## 适合与不适合

**适合**：本地存放不希望被直接翻看的照片、视频、文档；在移动硬盘或网盘上放加密副本；需要在加密状态下仍能随时查看的媒体库。

**不适合**：需要可否认加密（隐藏卷）的场景；需要抗内存取证或抗恶意软件的场景；把 `.omy` 当作唯一备份——密码遗忘没有任何找回途径。

关于威胁模型的边界，见[安全边界](/guide/security)。
