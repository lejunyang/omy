feat(core): 原子写入、会话密钥缓存与目录扫描

新增三个模块，并补上解析层的健壮性上界。

fsatomic — 原子写入（规范 §10）
  严格执行 tmp → fsync → fsync 父目录 → rename → fsync 父目录。
  只 fsync 文件是不够的：断电后可能出现内容完好但目录项丢失。
  Windows 无法 fsync 目录，NTFS 的 rename 自带日志，该步跳过。
  AtomicWriter 支持流式写入，未 commit 即 drop 会自动清理临时文件。
  TempPlaintext 处理「用外部应用打开」的旁路泄露：目录标记不索引
  （L3/L5）、drop 时覆写删除（L2）。覆写对 SSD 不保证物理擦除，
  已在文档中写明边界，不得对用户宣称「安全擦除」。

session — 会话密钥缓存（规范 §11）
  缓存键为 (vault_salt, 凭据类型, 标签)。含 vault_salt 是必需的：
  同一密码在不同 vault 下派生的 KEK 不同，若只用密码做键，切换 vault
  后会复用错误的 KEK，且表现为「密码错误」，极难排查。
  portable/recovery 不参与扫描（salt 因文件而异 / 需手动输入）。
  支持空闲超时自动锁定，默认 15 分钟。

scan — 目录扫描（需求 F-12）
  只读文件头即可识别并尝试解锁，载荷完全不碰——4 GiB 视频与 1 KiB
  文本的扫描成本相同。扫描过程不执行 Argon2，只做 HKDF（13 µs）。
  「打不开」与「损坏」严格区分：前者可能只是文件属于另一个密码集，
  UI 文案必须区别对待。单个坏文件不中断整次扫描。
  不做全盘扫描（iOS 不允许、Android 全盘权限难过审）。

解析层健壮性上界（规范 §8.3）
  header_len ≤ 64 MiB、tlv_len ≤ 32 MiB、TLV 条目 ≤ 4096、
  索引条目 ≤ 16M、chunk_size ≤ 64 MiB。校验在任何内存分配之前完成：
  否则一个 16 字节的恶意头部声明 tlv_len = 0xFFFFFFFF 就能触发 4 GiB
  分配，无需任何有效密钥。压缩索引的 entry_count 直接驱动
  Vec::with_capacity，是最危险的一处。

修正与发现
- chunk_size 只卡上限不卡下限。文档 §8.3 建议 MIN_CHUNK_SIZE=4096，
  但测试向量 v3/v4 用 4096/2048。向量是可执行的事实，且小块不构成
  DoS 风险（只会让文件略大）。误加下限曾导致 v4 向量失败。
- 修正扫描器的读取长度错误：曾误用 file::PEEK_SIZE（96，仅够解析
  固定头），导致读不到 slot 区（需 480），所有文件被误判为「损坏」。
  新增 scan::MIN_PROBE_SIZE 并在文档中说明两者区别。
- 新增 header::HEADER_LEN_FIELD_OFFSET 并配静态断言，替掉扫描器里
  的裸偏移量 12——布局若变更而常量未同步，会静默读到错误长度。
- decompress_chunk 统一约束解压输出不超过 chunk_size，堵住解压炸弹。

验证
- 102 项测试全绿：格式 31 + 恶意输入 23 + 运行时 34 + 向量 12 + doctest 2
- 恶意输入测试构造真实攻击载荷，确认上界确实拦下攻击而非死代码
- 会话测试直接验证性能主张：10 次解锁只跑 1 次 Argon2
- 扫描测试验证可否认性的实际效果：不同密码看到不同文件集，
  但看到的文件总数相同
- cargo clippy --all-targets -- -D warnings 零警告
